# RAG 检索评测

离线跑向量索引，只评检索层，不经过 LLM 生成——Query 改写与回答生成都不参与，
指标因此可复现、可对比。

## 怎么跑

```bash
cd mall-customer
python -m eval.run_eval              # 汇总指标
python -m eval.run_eval --verbose    # 逐条打印召回结果
python -m eval.run_eval --top-k 5    # 改 hit@k 的 k
```

首次运行若 `vector_store/` 为空，会自动从 `knowledge_base/` 导入并落盘（需调 embedding 接口）。
前置条件：`.env` 里的 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `EMBEDDING_MODEL` 已配置。

## 指标定义

| 指标 | 含义 |
|------|------|
| hit@3 | 知识库确有答案的问题，前 3 条召回里是否包含预期文档 |
| 空召回准确率 | 知识库没有依据的问题，检索是否如实返回空（不乱召回） |

两个指标都要看：只追 hit@3 会把阈值调低，代价是负样本全部被误召回，
用户问无关问题时 Agent 硬答。脚本在任一指标低于 70% 时以非零码退出。

## 数据集

`cases.json`，42 条：

- 32 条可回答：25 篇知识库文档基本各 1 条，另有 7 条是同义改写或高频追问（如「退货邮费谁出」「拆了包装还能退不」）
- 10 条负样本：闲聊、完全无关、越界诉求、知识库未覆盖的政策（加盟、比特币支付、打折内部价）

query 一律用用户口语，不照抄文档标题——照抄标题测不出真实检索能力。

## 当前结果

模型 `text-embedding-v4`，1024 维，阈值 `RAG_MIN_SCORE=0.5`，`top_k=3`。

```
用例总数     : 42
可回答用例   : 32
hit@3        : 31/32 = 96.9%
负样本用例   : 10
空召回准确率 : 9/10  = 90.0%
```

### 两个失败用例的成因

**未命中：「你们发不发货到我这个地方」** → 期望 `18-delivery-area`，实得 `05-logistics-tracking`（0.6193）、`04-shipping-time`（0.6082）、`14-address-change`（0.5854），目标文档排第 5（0.5758）。

这是 embedding 的口语-书面语错配，不是知识缺口：换成「哪些地方不发货」，目标文档排第 1（0.6284）。
同一句话换成「你们能送到我这里吗」则直接空召回——「送到」与「配送范围」的向量距离比阈值还远。
单条文档的标题与正文都是书面语，口语提问天然吃亏。

**误召回：「能不能给我打个折内部价」** → 召回 `23-points`（0.5324）。

会员积分文档谈「积分抵扣」，与「打折」在向量空间上挨得近，刚过 0.5 阈值。
要压掉它只能把阈值抬到 0.54 以上，但那样「我要投诉，怎么弄」（0.5619）这类合法问题也会掉出去——
阈值不是免费的，这是当前的取舍点。

### 为什么不去改文档

把「发不发货」这类说法写进知识库，hit@3 会立刻变成 100%，但那样测的是「有没有把测试题抄进答案」，
不是检索能力。要提升这一项，正确方向是改切分粒度（按小节切，让标题参与向量）
或换更适合中文口语的 embedding 模型，属于后续优化，不在本轮范围。
